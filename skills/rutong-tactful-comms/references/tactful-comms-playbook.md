# Tactful Comms Playbook

## 核心公式

Rutong 式委婉沟通通常按以下顺序组织：

1. **认可或中性背景**：说明对方的贡献，或解释为什么现在需要沟通。
2. **客观事实**：描述结果、差距、限制或依赖，不评价个人态度和能力。
3. **明确 Action**：谁在什么时候完成什么，或希望对方具体推动什么。
4. **支持或闭环**：说明 PMO 可以提供的帮助、完成后的下一步，或 ownership 不匹配时的转交方式。

这不是固定模板。信息很短时，可以省略没有实际价值的部分，但不能省略真正的 action。

## 1. 追进度与未达预期

避免：

> 你们为什么没有达标？请说明原因。

推荐逻辑：

> 近期【指标/交付】达成低于预期，我们想和各 team 对齐一下当前的主要原因、卡点和困难，也看看【PMO/我们】是否可以提供支持。方便的话，请在【时间】前同步【具体信息或行动】。

规则：

- 用“达成低于预期”描述事实，不用“表现不好”评价团队。
- `Support` 不能替代 action；仍需写清对方要回复或完成什么。

## 2. Ownership 不确定

避免：

> 这个是你负责的吧？麻烦尽快处理。

推荐逻辑：

> 想确认一下【事项】目前是你在 follow 吗？背景是【客观原因】。如果是，方便的话请帮忙【具体 action】；如果不是，也麻烦帮我指一下对应 PIC～

规则：

- 先确认 ownership，再分配责任。
- 给出“指向正确 PIC”的退出路径，但不要让事项无人承接。

## 3. 布置任务与 Deadline

避免：

> 大家别忘了交作业，本周必须交。

推荐逻辑：

> 请各 team 以【单位】在【DDL】前沉淀并提交【产物】。内容可围绕【范围】展开，后续我们会统一汇总用于【明确目的】。

规则：

- 把“作业”改成产物、总结、输入或 follow-up，除非场景本身适合轻松称为作业。
- DDL 必须明确；不要用“有空”“尽快”替代已确定时间。
- 解释产物会如何被使用，让要求显得合理，但不要虚构用途。

## 4. 请求跨团队或领导支持

避免：

> 麻烦帮忙 push 一下这个需求。

推荐结构：

> **Support Needed：**希望协助推动【具体事项】。
>
> **Background / Impact：**【为什么重要及量化或可观察影响】
>
> **Current Blocker：**【当前卡点、已完成动作和依赖团队】
>
> **Specific Ask：**希望帮助对齐【优先级、资源、owner 或 decision】。
>
> **Owner / ETA：**【执行 owner 和下一检查点】

规则：

- 不使用模糊的 `please review`，说清楚需要对方拍什么板。
- 保持平等语气，不用“冒昧”“烦请”“拜托”等堆叠式谦辞。

## 5. 限制、故障与 Mandatory Action

避免：

> 大家用得太猛，额度烧完了。下周必须更新，不然不能用。

推荐逻辑：

> 实际使用量增长快于原先预估，本周期额度已提前使用完毕。【真实影响】。新的额度将在【版本/时间】启用，请大家届时更新至最新版，更新后即可【恢复状态】。

规则：

- 把原因写成使用增长和预算机制，不责怪用户。
- 如果额度已经耗尽，直接写“已使用完毕”，不能写“接近上限”。
- 清楚说明 mandatory action、旧版本限制和恢复路径。
- 相对日期要和当前日期核对；未知版本或时间保留占位符。

## 6. 引导用户改变行为

避免：

> 不要再用贵模型了，太烧钱。

推荐逻辑：

> 先认可对方的偏好或目标，再重新分配场景：把高阶能力留给复杂判断和最终把关，让轻量方案承担高频执行、整理和试错。说明额度或成本约束，但不要把节省成本描述成体验降级。

规则：

- 不否定用户身份和选择。
- 给出容易尝试的替代路径，而不是要求一次性改变全部习惯。

## 7. 熟人或技术同事请教

面对熟人群聊，优先使用具体问题和个人玩家语气：

> 现在单次最多只能拿【数量】对吧？如果我想拿【数量】，能不能短时间多取几次再拼起来？会不会有限流？

避免把尚未确认的想法包装成正式架构或已支持能力。使用“能不能”“比如”“我想试试”等词保留探索性。

## 常见替换

| 容易引发压力的表达 | Rutong 风格 |
|---|---|
| 你们没达标 | 当前达成低于预期 |
| 解释一下为什么没做 | 对齐一下当前原因、卡点和困难 |
| 你负责这个吧 | 想确认一下目前是你在 follow 吗 |
| 帮忙看看 | 希望协助确认 / 推动 / 对齐【具体事项】 |
| 尽快处理 | 请在【明确时间】前完成【动作】 |
| 大家用得太多 | 实际使用量增长快于原先预估 |
| 强制更新 | 新能力/额度随新版本启用，请届时更新至最新版 |
| 一点心意 / 烦请 | 为表达感谢 / 请直接回复即可 |

## 最终检查

- 是否删除了对人的负面判断，但保留了客观问题？
- 对方是否一眼知道自己需要做什么、何时完成？
- 是否给了合理背景，而不是用背景稀释责任？
- 是否提供了真实的 support、转交路径或恢复方式？
- 语气是否平等自然，没有卑微、官腔或假夸奖？
