# Tactful Workplace Comms

## 目的

把可能引发压力或防御情绪的职场信息，改成对方更容易理解、接受和执行的表达。软化人际摩擦，不软化事实、责任、截止时间、影响和必要动作。

## 先读

处理敏感职场沟通时，读取：

- `references/tactful-comms-playbook.md`

## 判断顺序

1. 明确真实目的：确认负责人、催进度、要求交付、请求支持、通知限制，还是纠正行为。
2. 分开已确认事实、推断、必要动作、影响和可提供的支持；不把推断写成对人的评价。
3. 根据双方关系、沟通渠道和事项紧急程度调整语气，但保留一个明确的下一步。
4. 默认输出一个可直接发送的版本；只有语气强度会明显影响结果时，再提供更直接或更柔和的备选。

## 表达原则

- 仅在有实际信息时加入具体认可或中性背景，避免空泛夸奖。
- 描述可观察的现状、影响和限制，不把问题归咎于个人。
- 使用平等、自然的语气，避免过度道歉、恳求或官僚措辞。
- 负责人不确定时，允许接收方指向正确的人，但不能让事项因此无人承接。
- 必须完成的事项要写清负责人、动作和截止时间，不伪装成可选建议。
- 传达坏消息时，说明真实影响以及恢复路径或下一步。
- 避免反复使用“不是 X，而是 Y”，直接陈述希望对方理解和执行的结论。

## 边界

- 本 skill 只优化沟通，不替代业务判断。原文缺少已确认的负责人、截止时间、影响或理由时，保留占位符或指出信息缺口，不自行补造。
- 不编造原因、承诺、支持、完成状态或后果。
- 不为“委婉”牺牲清晰度；日期、数字或责任存在冲突时，先指出再改写。
- 生成可复用案例时，删除或泛化人员、组织、产品、项目、内部链接、真实指标及未公开流程。

## 输出标准

- 先给最推荐的 send-ready 文案。
- 匹配用户原文的语言、沟通渠道和正式程度。
- 保留受众日常使用的必要工作术语。
- 除非用户要求分析，只补充一句关键措辞逻辑，不展开长篇沟通理论。
