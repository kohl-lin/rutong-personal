# Rutong Tactful Comms

## 目的

把有压力的职场沟通改成对方更愿意接受和执行的表达。软化人际摩擦，不软化事实、责任、截止时间和必要动作。

## 先读

处理敏感沟通时读：

- `references/tactful-comms-playbook.md`

## 判断顺序

1. 明确真实目的：确认 owner、催进度、要求交付、请求支持、通知限制，还是纠正行为。
2. 分开事实、推断、行动、后果和可提供的支持；不把推断写成对人的评价。
3. 根据双方关系和事项强度调整语气，但保留唯一明确的 next action。
4. 默认输出可直接发送的版本；只有语气选择会影响结果时，再提供一个更直接或更柔和的备选。

## Rutong 风格

- 先认可具体贡献或交代中性背景，不做空泛夸奖。
- 描述客观现状和机制，避免把问题归咎于个人。
- 用平等、自然的语气提出请求，不使用过度谦卑或官僚措辞。
- 给对方合理台阶：ownership 不确定时允许其指向正确 PIC；探索性事项不伪装成强制任务。
- Action item 必须写清 owner、动作和 deadline；mandatory action 不写成“有空可以”。
- 坏消息应包含真实影响、恢复路径或下一步，不用模糊措辞掩盖事实。
- 避免反复使用“不是 X，而是 Y”，直接陈述希望对方理解和执行的结论。

## 边界

- AI PMO 事项如果还需要判断指标、优先级、ownership 或 support ask，先用 `rutong-ai-pmo` 完成内容判断，再用本 skill 处理表达。
- 不编造理由、影响、owner、ETA、支持承诺或已完成状态。
- 不为“高情商”牺牲清晰度；如果原文存在日期、数字或责任冲突，先指出再润色。

## 输出标准

- 先给最推荐的 send-ready 文案。
- 默认简洁中文，保留必要的英文工作关键词。
- 除非用户要求分析，只补充一句关键措辞逻辑，不展开长篇沟通理论。
