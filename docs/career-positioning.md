# Career Positioning and Evidence Rules

## 当前定位

- HR 正式职位保留为 `Business Intelligence`。
- 功能定位优先使用 `AI Strategy & Transformation`；`AI Portfolio Management / PMO` 是第二定位。
- `AI Eco Portfolio / PMO PIC` 描述实际职责，不替代正式职位名称。
- LATAM BI 属于潜在职责，确认前不进入正式履历。

## 履历工作流

1. 先维护完整事实库，再按目标岗位压缩成一页或两页简历。
2. 每条内容标记 `已确认`、`候选表述` 或 `待确认`；后两类不能伪装成正式事实。
3. 分开写个人可归因机制、个人直接交付、组织 adoption / impact 和 Portfolio scope。
4. 项目数、覆盖人数和组织指标只证明 scope；需要 ownership 与因果证据才能写成个人成果。
5. 部署、当前在线、活跃使用和 ROI 都是独立证据层；正式使用前重新核验容易变化的状态与口径。

## 证据优先级

- 先找 source artifact、工作记录、appraisal、tracker、usage data 或可验证产品状态。
- 机制型成果说明 Rutong 设计、推动或运营了什么，以及它改变了哪项决策或流程。
- 组织结果说明 Rutong 的可归因部分，避免把团队或 BU 的整体结果全量归为个人产出。
- 证据不足的问题保留为 open question，持续补 ownership、基线、结果和时间范围。
